Build an MVP Job Vacancy Matching Engine using Laravel.

## Goal

Create an application that automatically collects job vacancies and ranks them based on a manually configured candidate profile.

For the MVP, do NOT implement CV/PDF parsing. Candidate information will be entered manually to keep the system simple and low-cost.

Main flow:

Manual Candidate Profile  
→ Job Collector  
→ Job Normalization  
→ Hard Filtering  
→ Matching & Scoring  
→ Ranked Job Vacancy List

---

## Tech Stack

Use:

- PHP 8.3+
- Laravel 12
- MySQL or PostgreSQL
- Redis
- Laravel Queue
- Laravel Scheduler
- Blade
- Laravel Admin Panel optional, such as Filament

Prefer Laravel-native features before introducing additional dependencies.

Keep the architecture modular so job sources and matching algorithms can be extended later.

## 3. Job Sources

Create a generic job source architecture.

Use an interface:

```php
interface JobSourceInterface
{
    public function fetchJobs(): array;

```

Each provider should implement its own adapter.

Example:

```text
JobSourceInterface
├── GlintsJobSource
├── JobStreetJobSource
├── CompanyCareerJobSource
└── MockJobSource
```

Do not tightly couple the application to a specific provider.

Use dependency injection and Laravel's service container.

For the initial implementation, create at least one mock source so the matching system can be tested without depending on an external website.

Suggested structure:

```text
app/
└── Domain/
    └── Jobs/
        └── Sources/
            ├── JobSourceInterface.php
            ├── MockJobSource.php
            └── ...
```

## 7. Hard Filtering

Before calculating match score, reject jobs that clearly do not match the candidate preferences.

Examples:

```text
Candidate excludes internship
→ reject internship jobs

Candidate wants remote/hybrid only
→ reject onsite-only jobs

Salary is explicitly below candidate minimum
→ reject or mark as failed salary filter

Job requires significantly more experience
→ reject or heavily penalize
```

Hard filter logic must be separate from scoring logic.

Suggested structure:

```text
Job
↓
HardFilterEngine
↓
Accepted Job
↓
MatchingEngine
```

Example interface:

```php
interface JobFilterInterface
{
    public function passes(
        CandidateProfile $candidate,
        Job $job
    ): bool;
}
```

Individual filters can include:

```text
ExcludedKeywordFilter
WorkTypeFilter
SalaryFilter
ExperienceFilter
```

## 8. Matching Score

Use deterministic scoring.

Initial weights:

```text
Skill Match          40%
Role Match           25%
Experience Match     15%
Work Type Match      10%
Location Match        5%
Salary Match          5%
```

Formula:

```php
$totalScore =
    ($skillScore * 0.40)
    + ($roleScore * 0.25)
    + ($experienceScore * 0.15)
    + ($workTypeScore * 0.10)
    + ($locationScore * 0.05)
    + ($salaryScore * 0.05);
```

Return score between:

```text
0 - 100
```

Do not hard-code weights deep inside scoring logic.

Put weights in configuration:

```php
// config/job_matching.php

return [
    'weights' => [
        'skill' => 0.40,
        'role' => 0.25,
        'experience' => 0.15,
        'work_type' => 0.10,
        'location' => 0.05,
        'salary' => 0.05,
    ],
];
```

## 9. Skill Score

Skill score must consider candidate skill weights.

Example candidate:

```text
PHP         10
Laravel     10
MySQL        8
Redis        7
Docker       6
```

Job:

```text
PHP
Laravel
MySQL
AWS
```

Calculate match based on the total candidate skill weights.

Example concept:

```php
$matchedWeight = 28;
$totalCandidateWeight = 41;

$skillScore = ($matchedWeight / $totalCandidateWeight) * 100;
```

Do not treat all candidate skills equally.

Return:

- matched skills
- unmatched candidate skills
- job skills not present in candidate profile

## 14. Background Processing

Use Laravel Queue + Redis.

Use Laravel Scheduler to periodically dispatch jobs.

Create queue jobs such as:

```text
FetchJobVacancies
NormalizeJobVacancy
ExtractJobSkills
CalculateJobMatches
RefreshExpiredJobs
```

Flow:

```text
Laravel Scheduler
↓
FetchJobVacancies
↓
Deduplicate Jobs
↓
Normalize Job Data
↓
Extract Skills
↓
Hard Filter
↓
Calculate Match
↓
Store JobMatch
```

Example scheduling:

```php
use Illuminate\Support\Facades\Schedule;

Schedule::job(new FetchJobVacancies())
    ->everyThreeHours();
```

Do not perform long-running collection or matching directly inside HTTP requests.


```php
    public function match(
        CandidateProfile $candidate,

        //
    }
```

Create a `MatchResult` DTO rather than returning an unstructured array everywhere.

## 21. Important Engineering Principles

Follow these rules:

```text
Controllers should stay thin.

Do not put business logic inside controllers.

Avoid putting complex matching logic inside Eloquent models.

Use service classes for matching.

Use dedicated filters for hard filtering.

Use interfaces for job sources.

Use DTOs when passing structured matching results.

Use enums instead of magic strings.

Use config files for scoring weights.

Use queues for expensive/background processing.

Make all scoring deterministic and testable.
```

## Final MVP Objective

User flow:

```text
User configures profile
↓
User configures skills and weights
↓

Laravel Scheduler periodically triggers job collection
↓
Job vacancies are normalized
↓
Skills are extracted
↓
Duplicates are removed
↓
Hard filters remove irrelevant jobs
↓
MatchingEngine calculates scores
↓
JobMatch is stored
↓

User opens dashboard
↓
Highest matching vacancies appear first
```

The MVP must remain inexpensive to operate and must not require any paid AI API.

Prioritize:

1. simplicity
2. low operating cost
3. deterministic results
4. explainable scoring
5. testability
6. modular architecture
7. easy addition of new job sources
